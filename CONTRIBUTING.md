# Contributing

sniffarr does not accept code. It accepts proposals.

The reason is that writing code has stopped being the valuable part. With
coding agents a working change costs minutes, so a patch from outside saves
the maintainer little. Simon Willison puts the shift as
[writing code is cheap now](https://simonwillison.net/guides/agentic-engineering-patterns/code-is-cheap/),
and adds that good code still has a cost. Steve Ruiz closed tldraw to
external pull requests for the same reason, asking in
[Stay away from my trash!](https://tldraw.dev/blog/stay-away-from-my-trash)
why anyone else should write the code if writing it is the easy part.

What stays expensive sits on either side of the code:

- **Deciding what to build.** Which problem is real, for whom, and whether
  solving it is worth what it adds to the project.
- **Deciding whether the result is good enough.** Whether the change does
  what was meant, holds up, and fits the rest.

Both are the maintainer's work, and the first is where a contributor helps
most. A proposal is that help.

## Proposing a change

Open an issue on [GitHub](https://github.com/mikluko/sniffarr/issues) or on
[sarak.sh](https://sarak.sh/mikluko/sniffarr/issues). A bug report is a
proposal too: that something should behave differently.

A proposal is judged on how convincing its motivation is. The change itself
can be a sentence; the case for it is what takes the work:

- **The problem.** What happens now, where, and to whom. Real names, logs,
  queries and screenshots beat descriptions of them.
- **Why it matters.** What it costs you, and how often.
- **What should change.** The behaviour you want, as you would see it.
- **What you weighed.** Other ways out, and why this one.

## Pull requests

Pull requests are not merged. An idea in one is welcome as an issue, made
the case for as above.
